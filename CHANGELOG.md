### Added

- **A lib test pins the two skill references and the example-free agent descriptions** (W2272). `lib/test-structure.sh` gains a *Skill references and agent descriptions* section. It checks that `skills/session/references/session-artifacts.md` and `skills/bug-advocacy/references/worked-example-and-tone.md` exist and are linked from their skills; that each moved heading, the backlog and coverage-outline header blocks, and the worked-example table are in the reference and gone from `SKILL.md`; that the *Session artifacts on disk* and *Safety of session artifacts* stubs the commands cite are still there; that neither agent description carries an `<example>` block while each keeps its triggering conditions and, for the explorer, its safety statement; and that the trimmed `/explore`, `/pair` and `/harden` descriptions keep theirs.
- **A lib test pins the explorer's reading rule** (W2270). `lib/test-structure.sh` gains an *Explorer reading rule* section. It checks that `explorer.md` documents the *Reading files* section: locate first with `grep -n`; read a bounded range with `Read`'s `offset` and `limit`, never a large file when a range answers; never re-read a file or range already read this session, skills included; the changed-file exception, which re-reads only what changed; the binary-file rule; the sentence saying the credential-file rule is not loosened; and the pointer from *Optional codebase access*. It also checks that the explorer card carries none of this text, and that the test-account pointer provenance sentence is present.
- **The explorer has a verify mode that re-checks one fixed bug from its `minimal_repro` in one or two probes and returns pass or fail with evidence** (W2268). Re-checking a fix used to mean a whole new session, at least eight probes (the 8–20 band), to re-execute one known repro. With `EXPLORATORY_MODE=verify` — a line in the environment context, or its own argument — `agents/explorer.md` runs a charter built from the bug (`Explore <the fixed behaviour> with <the bug's minimal_repro> to discover whether <its observed failure> still occurs`) on a default budget of **2 probes / 10 tool calls**, band 1–2. A caller may raise the tool-call ceiling for a repro that needs setup state, never above the ordinary 60, but never the probe budget. Probe 1 executes the repro exactly; probe 2 runs only when `generalization` names a condition — after a pass, to catch a fix that covers only the literal repro, and after a fail, as RIMGEA's Generalize step. The output is the same JSON object plus one root key `verify` — `{ "result": "pass" | "fail" | "not_verified", "repro_reached", "evidence" }` — and the report-file summary gains a `verify: <result>` line. `pass` needs the repro reached and no element of the observed failure; a partial fix is `fail`, and its still-present defect goes in `bugs`; a repro that was not reached, or a bug with no usable `minimal_repro` (zero probes, `status: "blocked"`), is `not_verified`, which is never a pass. `stop_reason` keeps its five values. A verify pass covers that one bug only, never the original charter's other risks, and the smaller budget never relaxes the safety boundary. The explorer card is unchanged: verify mode lives outside it. **Without the variable nothing changes.** Exercised from source on 2026-10-04 by a general-purpose agent told to follow this `agents/explorer.md` verbatim against a disposable local CLI fixture with a seeded doubled-and-trailing-hyphen bug: the fully fixed script returned `verify: pass` in 2 probes, a script that fixed only the trailing hyphen returned `verify: fail` in 1 probe with the still-present doubled hyphen in `bugs`, and a bug record whose `minimal_repro` said "not established" returned `verify: not_verified`, `status: blocked`, in 0 probes. Five ambiguities that run reported are resolved in the text: the bug under re-check is never skipped as known-bad-but-expected, probe 2 serves Generalize after a fail, narrowing stays inside probe 1, a ceiling after a passing probe 1 leaves the pass standing, and `status` follows the verdict — superseded below by the `stop_reason` table (W2262). Not yet exercised as a dispatched agent: that loads the installed release, so `stride`'s Step 5.5 re-check takes its full-charter fallback until this is released.

Variants built from the fixture must pass (zero bugs, blocked before the first probe, `stopped_early` on the probe budget, a once-seen `1/5` Critical) and must be refused (a status that disagrees with `stop_reason`, a bug without `replicated`, a provisional mismatch, an undocumented root key, severity `Major`, `replicated` `1/1`, no `contract_version`). Set `EXPLORER_OUTPUT` to the absolute path of a real dispatch's report file and the same rules check it. `commands/explore.md` is pinned to handle `contract_version`, `known_bad`, `replicated`, `provisional` and the trust-`stop_reason` rule.
- **A lib test pins verify mode** (W2268). `lib/test-structure.sh` gains an *Explorer verify mode* section: `explorer.md` documents the variable, the 2-probe default and 1–2 band, the no-larger-probe-budget rule, probe 1 executing the repro, the no-improvised-repro rule, the three results, the partial-fix rule, that `not_verified` is never a pass, the one-bug scope of a pass, the unrelaxed safety boundary, the `verify:` summary line and the not-a-second-shape rule; and the explorer card carries no verify-mode text.
- **A lib test pins `/harden`'s unattended path** (W2269). `lib/test-structure.sh` gains a */harden unattended path* section: `commands/harden.md` documents the *Unattended invocation* rule, that it never calls `AskUserQuestion` when a bug source and `--framework` are both supplied, the reserved `none` value, *given but not found*, the skipped weak-evidence and competing-runner questions, the stop-not-menu rule for an unreadable source, the explorer report file as a bug source, the orchestrator-acts-for-the-operator clause, and that the credential, real-host and never-overwrite rules are still present.

The plugin skills count too: locate the section by its heading and read it once. **The one exception is a file that changed since it was read** — the app wrote it, or a log grew. ## [0.3.0] - 2026-10-02

An accuracy fix for the explorer: the rules that decide a bug's severity now travel inside the agent instead of in skills it never loaded, and the explorer can now write its findings to a file instead of the conversation.

### Changed

- **The explorer carries an inline explorer card, so its severity scale, oracles, RIMGEA and stop rules no longer depend on loading a skill** (W2261). `agents/explorer.md` told the agent to read `heuristics`, `oracles`, `bug-advocacy` and `session` by a plugin-relative path (`skills/<name>/SKILL.md`), but the agent has no Skill tool and runs in the project directory, where that path does not resolve. Measured over 19 `stride` Step 5.5 explorer dispatches between 2026-09-03 and 2026-10-02, the explorer loaded `bug-advocacy` once and never loaded the other three, and only 28 of 101 bugs carried one of the rubric's exact severity tokens (24 distinct severity strings, including `Major`, `important`, `medium` and whole sentences). Because `stride`'s fail-closed escalation keys on the literal `Critical`, that drift switched escalation off. The card — 3,750 bytes between `<!-- explorer-card:start -->` and `<!-- explorer-card:end -->`, placed directly after the unchanged safety boundary — holds the exact enum `Critical` | `High` | `Moderate` | `Minor` (a bare capitalised word, never omitted), every impact-ladder clause condensed per level, the tie rule, the three modifiers and their combination rule, the unknown-impact rule with its `Provisional` marker, the three oracle verdicts and the three kinds of oracle, RIMGEA mapped onto the `bugs[]` fields it fills, and the stop rules mapped onto `stop_reason`. The ladder's meaning is unchanged: no clause moved between levels. The `bugs[]` contract rows and the explore-loop steps now point at the card, and the four skills are optional depth, referenced as `${CLAUDE_PLUGIN_ROOT}/skills/<name>/SKILL.md`. The safety boundary is byte-identical.
- **How a plugin agent reaches plugin files, verified and recorded** (W2261). Claude Code's plugins reference (`code.claude.com/docs/en/plugins-reference`, *Where each variable resolves*, read 2026-10-02) lists "Skill, command, and agent content" with `${...}` resolving "Anywhere in the Markdown body", and states: "The variables aren't present in the environment of commands Claude runs through the Bash tool, in the main session or in a subagent. In skill, command, and agent content, write the `${...}` reference in the Markdown body instead, and Claude Code substitutes the path inline when it loads the content." So a plugin agent reaches its own files only through a literal `${CLAUDE_PLUGIN_ROOT}` written in its Markdown body; `$CLAUDE_PLUGIN_ROOT` inside a Bash call is unset, and a bare plugin-relative path resolves against the project directory and fails. This is **documented, not live-tested**: no installed plugin's agent used the variable as of 2026-10-02, and a dispatched agent runs from the installed cache, so the substitution is first exercised once this change is released. ## [0.2.0] - 2026-07-30

A capability sweep from the plugin's own 2026-07 improvement research: two new commands, a sixth skill, session artifacts that survive the conversation, and an explorer contract that no longer asks the agent to fabricate.

### Added

- **`interfaces` lens** — the Heuristic Test Strategy Model's **I**nterfaces element joins the coverage lens in the `chartering` skill, covering APIs, imports and exports, UI surfaces, and integration points between systems: the boundaries where service-oriented and LLM tool-calling applications most often fail. **Downstream consumers must handle `interfaces` as a new allowed value of a charter object's optional `lens` field** (`agents/charter-generator.md`), alongside the existing `structure`, `function`, `data`, `platform`, `operations`, and `time`.

- **`bug-advocacy` skill** — a sixth skill encoding Cem Kaner's **RIMGEA** (Replicate, Isolate, Maximize, Generalize, Externalize, And say it clearly), the discipline for the work between "an oracle says this is wrong" and a report someone will act on. It also defines **severity**, which the explorer's contract has always required and the plugin has never defined: a four-level rubric — **Critical > High > Moderate > Minor** — with an impact ladder of explicit clauses, three aggravating-only modifiers, and an agreement test, so two sessions rating the same bug from the same evidence land on the same level. The three existing severity words in the fixtures are preserved exactly; `Moderate` is the one new level. The skill also states the dispassionate-tone rule, including that inflated language — and an inflated severity most of all — costs the credibility that gets the *next* bug fixed. Routed from the orchestrator's routing table and handed off to from `oracles` at the point a result is classified a Defect.

- **`/harden` — a seventh command, and the plugin's first path from *Explored* back to *Checked*.** The thesis has always been **Tested = Checked + Explored**, but the two halves were only ever contrasted: a bug found by exploration stayed found, and nothing prevented its regression. Current practitioner guidance describes a **hybrid** model — manual, automated, and AI-assisted testing composed together — rather than exploration as a separate track, and `/harden` is that composition. It takes a session's **oracle-confirmed** bugs from a persisted session sheet, an `/explore` debrief, an `explorer` findings object, or pasted findings, and drafts a regression check per bug **from its `minimal_repro`** — RIMGEA's **Isolate** step already produces the shortest set of conditions that still triggers the failure, which is exactly what a minimal test case needs, so the field repays its cost a second time. **It detects the project's test framework rather than hard-coding one** (the plugin ships to arbitrary projects): existing test files first, confirmed against the ecosystem's manifest or test config across Elixir, JS/TS, Python, Ruby, Go, Rust, Java/Kotlin, .NET, and PHP, with one nearby existing test read for the suite's own conventions — and it **states what it detected, and on what evidence, before anything is written**. Two frameworks are resolved by subtree or by the bug's surface, or asked about once; none detected means it says so, writes nothing, and renders framework-agnostic Setup/Trigger/Assertion specs, never a guessed framework — `--framework <name>` is the operator's override. **Convertibility is an explicit four-part test** — a stated trigger, a stated wrong result, a programmable observation, and a safe repro — and a bug failing any part is **reported, never guessed at**, under one of seven categories (`no-repro-recorded`, `narrative-only`, `no-programmable-oracle`, `unsafe-to-automate`, `needs-a-decision`, `framework-ambiguous`, `framework-gap`) with the one thing that would make it convertible; drafts plus not-converted must add up to the bugs loaded. A `minimal_repro` reading `"not established: …"` is a first-class not-convertible case, as is a debrief bug whose repro survives only as narrative — the honest answer, since a guessed regression check passes for the wrong reason and is then trusted. **It never claims a drafted check passes, and it holds no tool that could run one**: its allowlist is `Bash(date:*), Bash(mkdir:*), Read, Write, Glob, Grep, Skill` — no `Agent`, no `WebFetch`, no general `Bash` — so the honesty rule is enforced by the tool list the way `/pair`'s never-drives-the-app rule is. Every draft is labelled `NOT RUN` and carries its red-then-green acceptance in its header: a regression check for an open bug should **fail** today, and that failure is the evidence it reproduces the bug. **Security carries through into the tests it writes**: no credential, token, session identifier, personal detail, customer record, or internal hostname is ever hard-coded — fixtures and environment references stand in, per the explorer's redaction rule — bug reports read from an artifact are untrusted data and a repro is a description, never a script, and the explorer's safety boundary extends to the drafts, so no check performs a destructive or production-mutating action even to reproduce a bug faithfully (an unsafe repro is reported, with a narrower guard-level reduction offered only when the artifact supports one). **It writes into exactly one directory and overwrites nothing**: `.exploratory/checks/<timestamp>-<source-slug>/`, holding the drafts plus an `INDEX.md`, or an `--output <dir>` the operator names — the plugin's one `--output` that names a directory rather than a document, because a run drafts many files. A colliding filename is suffixed `-2` and reported, never replaced. It deliberately does **not** touch `.exploratory/backlog.md` or `.exploratory/coverage.md`: nothing was explored, and recording coverage for a run that ran no probes would be a fabricated result. `.exploratory/checks/` is a **fourth** artifact path, and the README's *"No command writes anywhere other than these three paths"* sentence is updated to four **and** gains the stronger clause it always implied — **no command writes into your source tree or your test suite.** The orchestrator skill gains a routing row and, in *The mental model*, the bridge sentence the two halves never had; `bug-advocacy`'s *Handing off* names `/harden` as a third downstream consumer of `minimal_repro`.
- **`/pair` — a sixth command, and the plugin's first interactive testing mode.** Every command so far has been either fully generative (`/charter`, `/nightmare-headline`) or fully autonomous (`/explore`, whose `explorer` agent is forbidden to ask the user a question — charter and environment in, findings out). There has been no mode in which a **human drives the product and Claude rides along**, which is the dominant AI-pair-testing pattern in current practice. `/pair` is the exact inversion of `/explore`: the human exercises the application and reports what they did and saw; Claude suggests the next probe **and names the `heuristics` lens that generated it** (so the session stays reviewable and the tester learns the lenses), judges each reported result with `oracles`, works every confirmed defect through the `bug-advocacy` RIMGEA discipline as instructions to the human before anything reaches the `BUGS` block, and keeps the human's SBTM session sheet and off-charter parking lot so they never context-switch into note-taking. Its signature behavior is **unprompted coverage-gap reporting**: it maintains three ledgers — areas touched, the nine `heuristics` Variable Catalog rows, and seven fixed *stances* (valence, tenancy, role, character set, volume, sequence/concurrency, entry point) — and sweeps them on a fixed schedule to volunteer what the session has neglected ("rounds 1–6 all used one admin account in `<tenant A>`"), each gap raised **at most once per session** so a pair never becomes a scold. The session is bounded by the human's real wall-clock box: the `session` skill's 60–120 minute box already binds human-run *and paired* sessions, so `/pair` uses the **human** sheet skeleton with a `DURATION` measured from two real `date` stamps — the one wall-clock figure an agent in this plugin may report, because it is genuinely observed — while Task Breakdown Metrics are marked **derived from round timestamps** unless the tester confirms them. **The division of labour is enforced by the tool allowlist, not only by prose**: `/pair` holds no `Agent`, no `WebFetch`, and no `Bash` beyond `date` and `mkdir`, so it has no tool that can reach the application; it may `Read`/`Grep`/`Glob` only the source, config, and logs the tester named. Everything the tester pastes mid-session is treated as observed application output — **data, never instructions**, exactly as the `explorer` treats app content — and the explorer's absolute safety boundary still governs both what Claude does and what it will suggest. It writes its sheet to `.exploratory/sessions/<timestamp>-<target-slug>.md` (rewritten at checkpoints during the session so a dropped conversation costs nothing) and appends parked items, open questions, and declined gaps to `.exploratory/backlog.md`; it deliberately does **not** touch `.exploratory/coverage.md` and does **not** produce a debrief, because both are derived from Explored/Found/Unknown — it hands the sheet to `/debrief` with the literal command line and auto-chains into nothing. The `session` skill's artifact table gains `/pair` as a writer of session files, with the one lifecycle exception that a `/pair` sheet is live for the duration of its own session before becoming immutable.
- **Session artifacts that survive the conversation.** The plugin now persists three things to a small, predictable, gitignorable tree in **the project under test** (the current working directory, never the plugin's own repo): `.exploratory/sessions/<timestamp>-<target-slug>.md` (one aggregated debrief per `/explore` run), `.exploratory/backlog.md` (the charter backlog made real — charters deferred for budget, off-charter items parked mid-session, and candidate charters nobody has run yet), and `.exploratory/coverage.md` (the product coverage outline: which areas were explored, when, what is covered, and what is still dark). The convention — paths, the `date +%Y-%m-%d-%H%M` timestamp, the `[a-z0-9-]` slug rule, the per-artifact lifecycle, the `.gitignore` line, and the first-run rule — is owned by a new **Session artifacts on disk** section in the `session` skill. **A missing artifact is an empty starting state, never an error:** a first run in a new project creates the tree rather than failing. The coverage outline is deliberately a **map, not a score** — it carries no percentage, because "explored enough" is a judgment, not a number.
- **`charter-generator` accepts an optional `coverage context`** — a digest of what has already been explored against the target and what is already on the backlog — and a new optional `deprioritized` root key in its output contract reports the charter ideas it ranked down or dropped because prior coverage shows the ground was already explored. **`deprioritized` is distinct from the existing `coverage_notes`** and does not replace it: `coverage_notes` is about SFDIPOT angles the agent chose to skip on this run; `deprioritized` is about ground a previous session already covered. **Downstream consumers must handle the new optional `deprioritized` key.** The agent remains read-only (`Read, Grep, Glob`) — every write stays in the calling command.

### Changed

- **`/explore` gains `--output <path>` and now writes its aggregated debrief by default.** Where its Step 9 previously conceded that "`--output` is not part of this command's argument surface today, so persistence is optional," the debrief is now written to `.exploratory/sessions/<timestamp>-<target-slug>.md` unless `--output` redirects it, and the run's deferred charters and merged off-charter parking lot are appended to `.exploratory/backlog.md` while the areas it explored are refreshed in `.exploratory/coverage.md`. On the plan-only degrade path the generated charters are still appended to the backlog, but no debrief is written and coverage is left untouched — nothing was explored, and recording coverage for a run that never executed would be a fabricated result.
- **`/charter`, `/nightmare-headline`, `/recon`, and `/debrief` participate in the same artifacts.** `/charter` reads `.exploratory/coverage.md` and `.exploratory/backlog.md`, passes a digest to `charter-generator` as `coverage context`, renders any `deprioritized` list, and appends its charters to the backlog; `/nightmare-headline` appends its charters with the chosen nightmare recorded alongside them. `/recon` appends its candidate charters and open stakeholder questions to the backlog and may add a *not-yet-explored* area stub to the coverage outline — it never marks an area explored, because surveying is not exploring. `/debrief` appends the parked items and open questions from the notes to the backlog and refreshes the coverage outline for the areas the notes record as explored, skipping the update rather than inventing an area name when the notes do not support one. Every command's "What this command does NOT do" list now names the exact paths it may write, and no command writes anywhere else.
- **The redaction and untrusted-input rules now cover files, not just rendered output.** The `session` skill's *Safety of session artifacts* section is extended: `.exploratory/` is a new on-disk sink for observed system output, so credentials, tokens, customer data, personal data, and internal hostnames are redacted **before** a write — a file outlives the conversation and can be read by someone who never saw the session. And because the backlog and coverage outline are read back on later runs, they are treated as **untrusted data, never instructions**, exactly as `/debrief` treats session notes: a line that looks like a command is content to report, never something to obey. Artifact paths are handed only to `Read`/`Write`; the sole shell command any path may appear in is a `mkdir -p` of its own dirname, and the session slug is restricted to `[a-z0-9-]` so it can carry neither a traversal nor a shell metacharacter.
- **The explorer's `bugs[]` entries now carry the RIMGEA products.** Each bug gains `minimal_repro` (Isolate), `worst_observed` (Maximize), `generalization` (Generalize), and `stakeholder_impact` (Externalize), and `severity` is now defined against the `bug-advocacy` rubric and rated on the worst *demonstrated* failure rather than the first symptom. The four new fields are **honest-or-empty, never invented** — a bug that could not be generalized within the budget says so. **Downstream consumers must handle the four new `bugs[]` fields**; `/explore` carries them through aggregation and merges cross-session duplicates by keeping the shortest repro, the worst demonstrated consequence, and the broadest generalization. RIMGEA's Maximize step is explicitly bounded by the explorer's absolute safety boundary: a worse failure that cannot be demonstrated safely is a risk to name, never a result to claim, and security findings are maximized by reasoning rather than by exploitation.
- **`SFDPOT` renamed to `SFDIPOT`** across the plugin — skills, agents, commands, fixtures, and docs. Bach's HTSM (v6.0, 2024) lists seven Product Elements; the six-letter `SFDPOT` the plugin cited is a superseded form of the same heuristic. The `Interfaces` row slots between `Data` and `Platform`; no existing row was renamed, reordered, or dropped. The charter object's `source` enum value is still the literal `sfdpot` — it is a wire value, not the acronym, and renaming it would break existing consumers. The `[0.1.0]` entry below is left as written: it is a historical record of what that release shipped.
- **The `explorer` agent no longer reports numbers it cannot observe.** `session_sheet` drops `duration` and `tbs` (Task Breakdown Metric percentages) — a wall-clock measurement an agent has no way to take, whose presence contradicted the agent's own hard rule against fabricating a result. In their place it reports what it genuinely counts: `probe_budget`, `probes_attempted`, `probes_with_finding`, `on_charter_probes`/`off_charter_probes`, `tool_calls_used`, `heuristics_applied`, and `stop_reason`. An agent session is now bounded by an **agent-native budget** — a probe budget (default 12, band 8–20) and a tool-call ceiling (5 × the probe budget), whichever is reached first. The `session` skill keeps the 60–120 minute box and TBS for **human-run and paired** sessions and now states plainly that neither binds an agent session; the four stopping heuristics are unchanged in substance (bullet 2 now reads "The box or the budget is up"). **`/explore` gains `--probes <count>`** for the per-session probe budget; **`--timebox <minutes>` keeps its unit** and is now documented as doing only what it always effectively did — deciding how many charters run (one session ≈ 90 minutes) — and is never passed to the explorer. `fixtures/example-session-sheet.md` is now an agent-run sheet whose counts are derivable from its own notes. **Downstream consumers that read `session_sheet.duration` or `session_sheet.tbs` must switch to the counts**; `/debrief` is unaffected (it consumes unstructured tagged notes).

## Release process

This plugin is distributed through the existing [`stride-marketplace`](https://github.com/cheezy/stride-marketplace) catalog. **The plugin's `version` must stay in sync across two repositories.** To cut a release:

1. In **this repo** (`stride-exploratory-testing`): bump `version` in `.claude-plugin/plugin.json`, add a matching dated entry to this `CHANGELOG.md`, commit, `git tag vX.Y.Z`, and push the tag + a matching GitHub release.
2. In **`stride-marketplace`**: set the `stride-exploratory-testing` entry's `version` in `.claude-plugin/marketplace.json` to the **same** `X.Y.Z`, bump the catalog `metadata.version`, update `CHANGELOG.md` and `README.md`, commit, tag, and push.

The marketplace entry `version` and this plugin's `plugin.json` `version` must always match — a mismatch means `/plugin install` / `/plugin update` resolves a version that was never released.
